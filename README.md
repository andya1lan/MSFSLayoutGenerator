# MSFS Layout Generator

A double-click or drag-and-drop application for updating layout.json files in Microsoft Flight Simulator (2020) packages.

## Q&A
### Q. What is a layout.json?
A. The Virtual File System (VFS) in Microsoft Flight Simulator relies on a layout.json file in the root of each package to determine which files it is allowed to load, and to perform a basic file integrity check.

### Q. What does this application do?
A. The application will create/update a layout.json with all current files in the package folder and its subfolders. The following information is included with each file entry:
* File path relative to layout.json (including extension)
* Size (in bytes)
* Last modified time (represented as a [File Time](https://docs.microsoft.com/en-us/windows/win32/sysinfo/file-times))

The layout.json files generated by this application should be identical to those generated by Microsoft Flight Simulator. (Note: File order may vary, but shouldn't impact functionality of packages)

Additionally, if a package contains a manifest.json and the ***total_package_size*** property is present, the value will be updated to reflect the package's current total file size in bytes. The rest of manifest.json is left exactly as it is.

### Q. Who is this application for?
A. This application will benefit anyone who creates packages by hand rather than using the Project Editor in Developer Mode. Livery artists in particular may find this useful, as adding each texture to layout.json manually can be tedious.

### Q. Does this application work with Microsoft Flight Simulator 2024?
A. While any potential minor differences between MSFS (2020) and MSFS 2024 layout.json files have not been evaluated, the updated files generated by MSFS Layout Generator should function in MSFS 2024 as expected.

## Requirements
* Windows 10 or 11 (x64)

No .NET or other runtime is needed.

## Usage
1. Download the [latest release](https://github.com/HughesMDflyer4/MSFSLayoutGenerator/releases/latest) from this repository.
2. Update a package in one of these ways:
   * Put MSFSLayoutGenerator.exe in the package folder (next to manifest.json) and double-click it.
   * Drag the package folder, or its layout.json, onto MSFSLayoutGenerator.exe. Several packages can be dropped at once.
3. Check the result in the window, press any key to close it, then launch Microsoft Flight Simulator and check out your changes.

#### Notes
* The existing data in a layout.json will be overwritten/replaced when running the package through this application.
* A folder is only updated if it contains a manifest.json or a layout.json, so running the application from an unrelated folder (such as the Desktop) changes nothing.
* The following files are not listed in layout.json: layout.json and manifest.json in the package root, the application itself (even if renamed), MSFSLayoutGenerator.exe, and anything in the package root whose name starts with `_CVT_`.
* File paths longer than 260 characters are supported without enabling long paths in Windows.
* The application also runs from a terminal. Each argument is a package folder or a layout.json, as an absolute or relative path. With no arguments, it updates the folder the application is in. The exit code is 0 when every package was updated and 1 otherwise. Example:
```
MSFSLayoutGenerator.exe "G:\MSFS\Community\example-package-1" "G:\MSFS\Community\example-package-2\layout.json"
```

## Building from source
Requires [Go](https://go.dev/dl/) 1.24 or later. The Windows executable can be built on Windows, macOS or Linux:
```
make build      # dist/MSFSLayoutGenerator.exe
make test       # run the tests on this machine
make test-exe   # dist/MSFSLayoutGenerator.test.exe, runs the tests on Windows: MSFSLayoutGenerator.test.exe -test.v
```
Without make: `GOOS=windows GOARCH=amd64 go build -o dist/MSFSLayoutGenerator.exe .`

The icon, version information and Windows manifest come from `winres/winres.json`. After changing it, run `make winres` to regenerate `rsrc_windows_amd64.syso`.
